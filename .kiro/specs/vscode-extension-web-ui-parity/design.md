# Design Document: VS Code Extension Web UI Parity

## Overview

This design document specifies the implementation approach for enhancing the VS Code SQS Management Tool extension to achieve visual and functional parity with the web UI. The enhancement focuses on improving the user experience through refined styling, loading state indicators, and visual feedback mechanisms while maintaining full compatibility with VS Code's theming system.

### Goals

- Implement a polished, professional UI that matches the web application's visual design
- Provide clear loading state feedback for all asynchronous operations
- Enhance visual hierarchy and information organization
- Maintain full compatibility with VS Code light and dark themes
- Ensure all existing functionality remains intact

### Non-Goals

- Rewriting the extension architecture or communication patterns
- Adding new SQS management features beyond UI enhancements
- Implementing custom theming beyond VS Code's theme variables
- Creating a separate styling framework or CSS preprocessor setup

## Architecture

### Current Architecture

The VS Code extension uses a webview-based architecture with the following components:

```
┌─────────────────────────────────────────────────────────────┐
│                     VS Code Extension Host                   │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  extension.ts                                          │ │
│  │  - Queue tree provider                                 │ │
│  │  - Command handlers                                    │ │
│  │  - Webview panel management                            │ │
│  │  - getWebviewContent() - generates HTML/CSS            │ │
│  └────────────────────────────────────────────────────────┘ │
│                           ↕ postMessage API                  │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  Webview (Sandboxed Browser Context)                   │ │
│  │  ┌──────────────────────────────────────────────────┐  │ │
│  │  │  HTML Content (generated by extension.ts)        │  │ │
│  │  │  - Embedded CSS styles                           │  │ │
│  │  │  - Tab structure                                 │  │ │
│  │  │  - Form controls                                 │  │ │
│  │  └──────────────────────────────────────────────────┘  │ │
│  │  ┌──────────────────────────────────────────────────┐  │ │
│  │  │  main.js (webview-side JavaScript)               │  │ │
│  │  │  - Event handlers                                │  │ │
│  │  │  - Message display logic                         │  │ │
│  │  │  - View mode switching                           │  │ │
│  │  └──────────────────────────────────────────────────┘  │ │
│  └────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
                           ↕
                    AWS SQS API (via api.ts)
```

### Design Approach

All styling enhancements will be implemented through:

1. **CSS Updates in extension.ts**: Modify the embedded `<style>` block within the `getWebviewContent()` function
2. **JavaScript State Management in main.js**: Add loading state tracking and dynamic UI updates
3. **HTML Structure Updates in extension.ts**: Add new elements (header bar, badges) to the generated HTML

This approach maintains the existing architecture while enhancing the visual presentation and user feedback mechanisms.

```javascript
    badge.style.display = 'none';
  }
}
```

### 4. Loading State Management

**Implementation Strategy**: Track operation states and update button text/disabled state

**State Tracking Variables** (in main.js):

**Button Update Functions**:
```javascript
function setButtonLoading(buttonId, isLoading, loadingText, defaultText) {
  const button = document.getElementById(buttonId);
  if (!button) return;

  button.textContent = isLoading ? loadingText : defaultText;
```

## Data Flow

### Loading State Flow

```
User clicks button
    ↓
JavaScript: Set loading state = true
    ↓
JavaScript: Update button (disabled, loading text)
    ↓
JavaScript: Send postMessage to extension
    ↓
Extension: Process request (async)
    ↓
Extension: Send response postMessage
    ↓
JavaScript: Receive response
    ↓
JavaScript: Set loading state = false
    ↓
JavaScript: Update button (enabled, default text)
    ↓
JavaScript: Update UI with results
```

### DLQ Badge Update Flow

```
DLQ messages loaded
    ↓
JavaScript: Count messages in response
    ↓
JavaScript: Update badge count
    ↓
JavaScript: Show/hide badge based on count
    ↓
User performs redrive/delete operation
    ↓
Operation completes
    ↓
JavaScript: Refresh DLQ messages
    ↓
JavaScript: Update badge count (loop back)
```

### View Mode Toggle Flow

```
User clicks view mode button
    ↓
JavaScript: Update messageViewMode variable
    ↓
JavaScript: Update button active states
    ↓
JavaScript: Call updateMessagesDisplay() or updateDLQMessagesDisplay()
    ↓
JavaScript: Re-render messages in new format
    ↓
DOM updated with card or table view
```
